# 01: 起播前 Audio Focus 窄门控与宿主硬件锁对称收敛

**What to build:** 打通生产环境起播前 `Audio Focus` 申请门控并将硬件锁全生命周期收敛至系统宿主。在物理流引擎上暴露极窄的起播前门控注册接口，由系统宿主绑定 `AudioFocusHandler` 的焦点申请方法；当系统拒绝授予 `Audio Focus` 时直接阻断底层起播并保持暂停，绝不发出短暂破音或启动无效网络缓冲，同时保留“来电瞬态让渡期间用户手动暂停则挂断后不自动续播”与不重复降音语义。同步将硬件唤醒锁与 Wi-Fi 锁的持有、申请与释放完全收拢至系统宿主，彻底移除应用级 `Playback Session` 对底层硬件锁实现的反向依赖。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 物理流引擎提供起播前窄门控挂钩，未获放行时调用起播或带起播意图的加载不激活底层播放器发声
- [ ] 系统宿主将 `AudioFocusHandler` 焦点申请绑定为引擎起播门控，实现生产路径真实抢占与拒批拦截，同时保持暂停、出错、结束、空闲及宿主解绑时的焦点放弃与硬件锁对称释放
- [ ] 来电等瞬态失去 `Audio Focus` 时自动暂停并在恢复后自动续播；若用户期间手动暂停或已停止，恢复焦点后不自动续播
- [ ] 应用级 `Playback Session` 及其测试完全剥离底层硬件锁类型引用与锁桩对象，宿主与焦点回归测试全部通过针对性单测验证
